# Native capture and output contracts

This package is phone-local Swift source for an iPhone implementation. It has no Mac server, HTTP client, external dependency, model download, account setup or permission request. The Mac commands below compile and test the source during development; they are not the product runtime.

The Foundation/CryptoKit coordinator accepts injected on-phone recognizer, chess-rules, engine and speech implementations. No permissive default rules, model or engine is supplied. The local JavaScript rules/Stockfish service can implement these protocols through a separately verified on-device WebKit binding. Merely creating a `CaptureCoordinator` or importing this package starts no processing, SDK or audio.

## What the boundary guarantees

- Frames receive immutable session UUID, epoch, sequence and SHA-256 of the exact encoded bytes submitted to recognition. A new frame immediately revokes review, analysis and output. There is one active recognizer and one latest pending frame; a cancelled task occupies its slot until it actually returns, including across reset/reconnect.
- Recognizer proposals contain 64 piece observations and no inferred FEN, turn, castling, en passant or counters. Complete observations still require an independent explicit review of all five state groups and validation by an actual local chess-rules implementation. This package does not implement a review UI. Unknown proposals cannot be confirmed by this path.
- Review is bound to a particular frame and revision. Engine results must echo the complete request identity and pass the local rules adapter's legal-move check. Spoken text is regenerated by that rules adapter. No recognizer confidence or engine `humanReviewed` assertion can authorize output.
- A speech permit is bound to the frame, reviewed full FEN, revision, request UUID and capture-age expiry. A 50 ms watchdog revokes expired queued/playing output. The sink must check `isCurrent` immediately before enqueueing and stop synchronously in `cancel`. Late completions cannot cancel a newer speech attempt.
- Camera-active, interrupted, stop-requested-but-unacknowledged, terminal-position and speech-experiment-disabled states block analysis/output. A stop acknowledgement must match the epoch and stop request UUID. Receiving another frame invalidates a previous acknowledgement. The user must explicitly enable the speech experiment. This stop guard is **not a claim that Gen 1 audio routing works**.
- Pre-fixture repetition history remains incomplete; `historyComplete` is always false. A complete FEN cannot establish that history.

## Clock domains and the current live blocker

`receivedAtHostSeconds` uses `ProcessInfo.processInfo.systemUptime`. DAT `CMSampleBuffer` presentation timestamps are stored separately as media value/timescale. They are **not** treated as host monotonic capture times, and receipt time never substitutes for capture time.

Every DAT frame is `.unknownDAT`: **real DAT frames cannot obtain an engine or speech permit in this implementation**. A validated media-to-host clock mapping and hardware latency evidence are still required. Only the explicitly named `submitReplay` entry point can provide a trusted same-domain capture timestamp for tests. Never use it as a DAT workaround. Backward/future timestamps, wrong clock domains and expired frames fail closed.

## Dormant iOS adapters

`IOSAdapters.swift` is compiled only for iOS when `MWDATCore` and `MWDATCamera` are available. It targets the already acquired DAT **1.0.1**, revision `0bd369298eef6a980ad0bdb6c8a5502f2c02a08c` public interfaces. There is no package dependency fetch.

`DATCaptureAdapter.start(in:)` requires an already-started, explicitly authorized `DeviceSession` supplied by the host app. It calls `addCamera`, attaches bounded frame/state/error listeners, and explicitly starts a raw medium-resolution, 2 fps stream. It does not call `Wearables.configure`, use `Wearables.shared`, register, start the device session or request camera/Bluetooth permission. Frame callbacks enter a `bufferingNewest(1)` stream before any actor task, so JPEG conversion does not create an unbounded backlog. JPEG bytes are the identity/recognition input; original sample-buffer bytes are not claimed to be preserved.

`requestStop()` waits for a matching stopped state before acknowledging the stop. `disconnect()` invalidates identities, stops the camera, closes the bounded stream and cancels listeners. Pauses, session loss and errors revoke state. The host app must explicitly call disconnect when leaving capture.

`NativeSpeechOutput` uses `AVSpeechSynthesizer` only when its explicit `speak` method is called. It changes no audio session/category/route and makes no permission request. It has not been played on this Mac or on a phone/glasses pair.

## Local verification

Ten standalone contract checks use **mock pixels, mock chess rules, mock engine output and a mock speech queue**. They are lifecycle tests, not recognition accuracy, chess correctness, phone performance or hardware evidence. They cover queue bounds, immutable hashes, cancellation across reconnect, unknown DAT capture age, review/stop/terminal checks, new/uncertain/invalid frames, late engine output, illegal move rejection, expiry, clock rollback, and late speech completion.

Run from the repository root using the installed compiler and a package-local module cache:

```sh
swiftc -parse-as-library -swift-version 6 -D STANDALONE_CONTRACT_TESTS \
  -module-cache-path native/ChessCompanionCapture/.build/direct-mac-module-cache \
  -o native/ChessCompanionCapture/.build/capture-contract-checks \
  native/ChessCompanionCapture/Sources/ChessCompanionCapture/*.swift \
  native/ChessCompanionCapture/Tests/ChessCompanionCaptureTests/CaptureCoordinatorTests.swift
native/ChessCompanionCapture/.build/capture-contract-checks
```

On this development machine, the direct test binary passed **10/10**. SwiftPM's manifest sandbox could not start (`sandbox-exec: sandbox_apply: Operation not permitted`); no expanded permission was requested. Direct compilation used the existing Codex sandbox and package-local caches.

The complete source also passed a direct `swiftc -typecheck` targeting `arm64-apple-ios17.2`, with the installed iOS **26.2** SDK and the local DAT Core/Camera framework slices. This checked public API and Swift concurrency compatibility without SDK runtime calls, linking an app, signing, pairing, device access or audio. It does not verify the user's iPhone 17 / iOS 27.2 device compatibility or deployment. Re-run that check with `-F` pointing at each local `MWDATCore.xcframework/ios-arm64` and `MWDATCamera.xcframework/ios-arm64` slice; no fetch/install command is part of this package.
